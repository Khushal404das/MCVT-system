MCVT · Agent-based Vision Mixer for Video Broadcasts

MCVT Code Guide

What every file in D:\MCVT-system\mcvt does and how the files work together. The system has three running parts: a Python AI engine, a PHP WebSocket hub and a PHP web dashboard. All three share one SQLite database and one config.yaml.

How it fits together

The path of one car, from camera to emailed video. Each step lists the files that do the work.

  1. 1
    Read cameras. One background thread per camera (C11 … C61) reads the video and keeps only the newest frame. All recordings share one clock that starts at 08:00:00.
    camera.py · config.py · prepare_streams.py
  2. 2
    Detect. YOLOv8n, fine-tuned on these cameras, finds cars, buses, trucks and motorcycles. A background model keeps only the moving ones.
    detector.py · camera.py (MotionMask)
  3. 3
    Track inside one camera. DeepSORT gives each car a local track id and a Kalman filter predicts it through short occlusions.
    tracker.py · flow.py
  4. 4
    Re-identify across cameras. ResNet50-IBN turns crops into 2048-number feature vectors. Cosine similarity ≥ 0.64, plus the camera route, travel time, colour and type, decide the global id (VH-…).
    reid/resnet_ibn.py · reid/extractor.py · matcher.py · attributes.py
  5. 5
    Switch cameras. For a followed car every camera gets a score (box size × resolution weight). A Bayesian belief, a 0.15 hysteresis margin, a 5-frame buffer and a 3-frame fallback choose the camera shown.
    switching.py · pipeline.py
  6. 6
    Save and stream. Vehicles, features, sightings and logs go to SQLite. Frames and events go over a WebSocket to the PHP hub, which forwards them to every signed-in browser.
    db.py · bridge.py · logbus.py · WsServer.php
  7. 7
    Dashboard. The operator watches the grid, clicks a car to follow it, replays its journey and asks for the full video.
    index.php · app.js · api/*.php · media.php
  8. 8
    Journey video and email. The request is queued in the database. A worker thread collects the clips, FFmpeg stitches them in time order, and the video is emailed over SMTP if an address was given.
    jobs.py · stitcher.py · emailer.py · api/journey.php

Project root

Settings, database layout, start-up script.

config.yamlConfig426 lines

The one settings file read by both Python and PHP, so no threshold is hard-coded (NFR-M-02).

  • paths / server: database file, web port 8080, WebSocket port 8090.
  • cameras: find videos in ../dataset, ids from file names (camera_c21.mp4 → C21), shared clock 08:00:00, per-camera overrides.
  • detection: model yolov8n_mcvt_v2.pt, confidence 0.50. tracking: DeepSORT max_age 8, n_init 1.
  • reid: weights mcvt_reid_e2e.pth, similarity threshold 0.64, hand-off/follow thresholds, route between cameras, colour/type rules.
  • switching: hysteresis 0.15, buffer 5 frames, fallback 3 frames. stitching / email: FFmpeg and SMTP (port 587).
schema.sqlDatabase99 lines

Creates the SQLite tables shared by the engine and the website:

  • users, ws_tokens: operator logins and short-lived WebSocket tokens.
  • cameras: id, name, resolution, FPS, resolution weight, status.
  • vehicles: global id (VH-…), type, colour, first/last seen, thumbnail, merged_into.
  • embeddings: the feature vectors (the ReID "gallery").
  • sightings: one visit of a car to one camera (start/end time, video offsets, boxes). These are the clips for the journey video.
  • switch_events, jobs, logs: camera switches, journey-video requests, system log.
start.batStart-up10 lines

Opens three windows: the WebSocket hub (ws-server.php), the web server (serve.php), and the AI engine (prepare_streams.py then run_engine.py).

Python packages: ultralytics (YOLOv8), deep-sort-realtime, torch/torchvision, opencv-python, ffmpeg-python, imageio-ffmpeg, PyYAML, numpy, websocket-client, pytest.

Entry point of the AI engine. Loads config.yaml and starts Pipeline(cfg).run().

engine/prepare_streams.pyEngine61 lines

One-time step that writes a small 960 px / 10 FPS copy of each camera video to storage/streams/, like an IP camera's sub-stream. The AI and live view use the small copy so a CPU-only laptop keeps up. Journey videos are still cut from the full-quality originals. Videos already converted are skipped.

Engine core engine/mcvt/

The Python AI engine. Each module is one component, so it can be replaced on its own (NFR-M-01).

pipeline.pyEngine1707 lines

The heart of the engine. One loop takes the newest frame of every camera and runs detection → tracking → ReID → switching, then updates the database and streams results to the hub.

  • Pipeline: the main loop. Picks which cameras to analyse this cycle (busy and followed cameras first), joins broken tracks of one car, removes duplicate boxes, gives ids, ends tracks, writes sightings, sends vehicle lists and stats.
  • Operator commands: _on_command receives "follow VH-…" from the dashboard. _update_switching and _update_handoff keep the best camera on screen and search the next cameras when the car leaves.
  • ReIDWorker: a thread that runs the slow ResNet on crops so the main loop never waits.
  • FrameStreamer: sends video at the camera's own frame rate with boxes interpolated between AI results (live view is 2.5 s behind real time so boxes sit exactly on cars).
  • TrackRecord / VehicleLive: what is known about one local track and one global vehicle. stamp_clock: covers the camera's own timestamp and writes the shared clock.
camera.pyEngine302 lines

Reads cameras (video file or RTSP), one thread each, keeping only the latest frame. A failed camera is retried without stopping the others (NFR-R-02).

  • CameraStream: reader thread, resolution/FPS probing, status. FramePacket: one frame plus its camera, time and offset.
  • MotionMask: background model per camera. Parked cars fade into the background, moving cars show up.
  • PlaybackClock: starts all recordings together and restarts them together. assign_resolution_weights: works out w_r from each camera's resolution.
detector.pyEngine85 lines

Vehicle detection with YOLOv8 (FR-VD-01..05). VehicleDetector keeps only vehicle classes above the confidence threshold. detect_batch runs all cameras in one pass. Detection holds the box, class and confidence.

tracker.pyEngine85 lines

Tracking inside one camera with DeepSORT (FR-TR-01..04). CameraTracker is one DeepSORT per camera: local ids, Kalman prediction while a car is hidden, removal after max_age missed frames.

flow.pyEngine60 lines

Keeps boxes on moving cars between AI updates. FlowBoxes follows points inside each box with Lucas-Kanade optical flow and moves the box with them.

matcher.pyEngine697 lines

Cross-camera re-identification and global ids (FR-RI-02..04). This decides whether a car is new (VH-…) or one seen before.

  • CrossCameraMatcher: keeps the feature gallery. matchAcrossCameras compares a track with every stored vehicle by cosine similarity, and the highest score above the threshold gives the id.
  • Rules: one id can't be live on two cameras that don't overlap; two tracks in one camera never share an id; colour/type must agree.
  • Route and timing: route_candidates, typical_travel and expected_next learn which camera comes next and how long the drive takes. link_overlap joins the two gate cameras C11 + C21 that see one car at the same moment.
  • Fixing mistakes: find_merge / merge fold a duplicate id into the real one; displace takes an id from a weaker match.
  • TrackIdentity: the crops of one track waiting for an id.
attributes.pyEngine193 lines

Vehicle colour and type, used to reject wrong matches.

  • ColorNamer: names the body colour after removing each camera's colour tint (C31/C41 look blue). The learned tint is saved to storage/color_cast.json.
  • AttributeGate: a stored vehicle whose colour or type clearly differs (white vs black, car vs motorcycle) can't give its id. Near shades (white/silver) still match.
  • VoteBox: majority vote that steadies noisy per-frame readings.
switching.pyEngine144 lines

Camera scoring and switching (FR-CS-01..06), the "vision mixer".

  • camera_score: box area ÷ frame area × resolution weight.
  • CameraSwitchingEngine: a small Dynamic Bayesian Network keeps a belief per camera. A new camera must beat the current one by 0.15 (hysteresis) for 5 frames in a row (buffer). If the current camera loses the car for 3 frames, it falls back at once.
  • handleOverlapZone / OverlapDetection: when several cameras see the car, keep the best one.
db.pyEngine140 lines

SQLite access. Database is a thread-safe wrapper in WAL mode: create vehicles, store/load embeddings, upsert cameras, merge vehicles, write logs, and claim_job so each journey request is taken by one worker only.

jobs.pyEngine120 lines

Journey-video requests (UC-12..14). JourneyWorker is a background thread that picks queued jobs, runs collect_clips (all sightings of the car, in order, padded), stitches them and emails the result. resolve_gid follows merges (VH-007 → VH-002). Slow FFmpeg or SMTP never blocks live tracking.

stitcher.pyEngine171 lines

Journey video with FFmpeg (FR-VS-01..05). VideoStitcher sorts clips by time, removes overlaps so each moment comes from the best (highest-resolution) camera, cuts the pieces and joins them into one H.264 MP4. Missing or broken clips are skipped. find_ffmpeg finds the FFmpeg program.

emailer.pyEngine95 lines

Email delivery over SMTP (FR-ED-01..04). EmailService: attachVideo then sendEmail, which returns true or false and never crashes the engine. The login comes from .env (SMTP_USER / SMTP_PASSWORD), never from code (NFR-S-01).

bridge.pyEngine133 lines

The engine's WebSocket client to the PHP hub. Bridge sends JSON events and binary frames (header length + JSON header + JPEG), keeps only the newest unsent frame per camera, reconnects on its own, and passes operator commands back to the pipeline.

config.pyEngine150 lines

Loads config.yaml and .env and finds the cameras. Config gives dotted access (cfg.get("reid.similarity_threshold")). CameraSpec describes one camera. clock_seconds / format_clock convert "08:00:00" ↔ 28800 s. ensure_env creates a random engine token.

logbus.pyEngine51 lines

Plain-English system log (NFR-U-03). Each message goes to a rotating log file, the logs table and the dashboard's live log panel.

__init__.pyEngine7 lines

Marks mcvt as a Python package and states the layers: detection → tracking → ReID + switching → output.

ReID model engine/mcvt/reid/

The network that turns a vehicle crop into a feature vector.

resnet_ibn.pyEngine136 lines

ResNet50-IBN-a network written in plain PyTorch, so the public VeRi-776 weights load without installing FastReID. IBN layers (half Instance-Norm, half Batch-Norm) make features robust to colour and light differences between cameras (FR-RI-05).

  • IBN, Bottleneck, NonLocal, ResNetIBNBackbone: the network layers. GeneralizedMeanPoolingP + EmbeddingHead: pooling to a 2048-d vector.
  • ResNetIBNReID.load_fastreid_checkpoint: loads weights safely (tensors only).
extractor.pyEngine87 lines

FeatureExtractor.extractFeatures resizes crops, runs the network and returns unit-length vectors (FR-RI-01). ReIDAdapter is an optional learned projection for these cameras. color_histogram is a cheap colour descriptor that DeepSORT uses on CPU.

sequence.pyEngine59 lines

Optional GRU (RNN) that turns a track's crops, in time order, into one signature. SeqReID is the network and SequenceAggregator applies it.

In the current config.yaml, reid.sequence_model is empty, so the engine averages crop features. The ResNet weights in use (mcvt_reid_e2e.pth) were trained together with a GRU, so that training is what improved the features.
__init__.pyEngine1 line

Marks reid as a package.

Web server & WebSocket hub web/

Plain PHP 8 with no Composer packages: login, dashboard and the live hub.

lib/WsServer.phpWeb455 lines

The WebSocket hub (RFC 6455), written by hand on PHP streams. The engine connects with the secret engine token; browsers connect with a short-lived token from their login.

  • handshake / decodeFrames / encode: the WebSocket protocol itself.
  • broadcast: sends engine events and video frames to every browser. Slow browsers drop old frames instead of lagging.
  • onMessage / sendFocusSet: passes each operator's "follow this vehicle" choice to the engine.

Training engine/training/

Scripts used once to build datasets and train the models. The live system doesn't run them. No hand labelling was needed: a big "teacher" model or tracking produced the labels.

make_dataset.pyTraining79 lines

Detector dataset: a large YOLOv8m labels frames from every camera ("pseudo-labels").

train_detector.pyTraining43 lines

Fine-tunes YOLOv8n on that dataset on the CPU and saves yolov8n_mcvt.pt (detector v1).

export_detector_frames.pyTraining83 lines

Exports frames for GPU training, mostly the moments just before a car was first detected, when it was far away and still missed.

kaggle_finetune_detector.pyTraining146 lines

Kaggle GPU script: YOLOv8x at 1280 px labels the frames, then YOLOv8n is trained on them (detector v2, yolov8n_mcvt_v2.pt, the one in use).

evaluate_detector.pyTraining59 lines

Compares detectors on held-out frames: precision, recall, F1 and speed.

make_reid_dataset.pyTraining182 lines

ReID dataset: cuts each camera's video into tracklets of moving cars (one tracklet = one car in one camera) and saves crops.

train_reid_adapter.pyTraining332 lines

CPU method: an LDA projection (2048 → 512) learned on the project's cameras, with cross-camera pairs found from overlapping cameras and timing. Superseded by the fine-tuned weights.

train_reid_head.pyTraining247 lines

CPU method: a small head on the frozen ResNet trained with triplet + ID loss. Also superseded.

export_colab_dataset.py · make_colab_notebook.pyTraining58 / 299 lines

Pack the crops and write the Colab/Kaggle notebook that fine-tunes the whole ResNet50-IBN on a GPU (gave mcvt_reid_finetuned.pth).

kaggle_train_gru.pyTraining306 lines

First RNN try: a GRU on frozen ResNet features. It didn't beat the plain average, because the frozen features already separated the training cars perfectly.

kaggle_train_gru_e2e.py · make_colab_rnn.pyTraining323 / 100 lines

The final method: ResNet50-IBN and a GRU trained together end-to-end on augmented image sequences (blur for far cars, crop, colour). This produced mcvt_reid_e2e.pth, the weights in use. make_colab_rnn.py packs it for Google Colab.

calibrate_handoff.pyTraining89 lines

Measures how similar the same car looks across cameras and saves crop pictures, to help set the hand-off thresholds.
